# Chauhan Properties API

Base URL for local development: `http://localhost:5000`. JSON requests use UTF-8. Admin routes require `Authorization: Bearer <token>` except the two login-code routes.

## Common rules

- List endpoints return `{ "items": [], "page": 1, "page_size": 20, "total": 0 }`.
- List page size defaults to 20 and is capped at 100. Dates are ISO 8601 timestamps in UTC.
- Property areas are generated by PostgreSQL and cannot be written by clients.
- Public property responses omit buyer, sale price, and Cloudinary public IDs. Sold listings are shown by default; set `PUBLIC_SOLD_PROPERTIES=false` to hide them.
- Database/customer text is returned as plain JSON text. The admin UI renders it with `textContent`.
- Errors use `{ "detail": "A readable message" }`. Common statuses: 401 (missing/expired login), 404 (not found), 409 (conflict), 422 (invalid input), 429 (rate limit), 503 (provider unavailable).

## Authentication

| Method and path | Caller | Input | Success |
|---|---|---|---|
| `POST /api/admin/auth/request-code` | Public | `{ "email": "admin@example.com" }` | Always returns `200 {"message":"If this email is allowed, a code has been sent."}` for email-based decisions. Codes are 8 digits, expire in 10 minutes, and are limited to 3 requests/hour and 10/day per admin email; old unused codes are cancelled only after email delivery succeeds. Request IPs are limited to 5/hour (429). In local `DEBUG=true`, the code is printed to the server terminal. |
| `POST /api/admin/auth/verify-code` | Public | `{ "email": "admin@example.com", "code": "12345678" }` | `200 {"access_token":"…","token_type":"bearer"}`. Invalid, expired, or exhausted codes return 400. Verification IPs are limited to 10/hour (429). |
| `GET /api/admin/auth/me` | Admin | Bearer token | `{ "email": "…" }` |

## Properties

`GET /api/admin/properties` and `GET /api/public/properties` accept `property_type` (`plot`, `house`, `flat`), `status` (`available`, `sold`), `min_price`, `max_price`, `sort` (`newest`, `oldest`, `price_asc`, `price_desc`), `page`, and `page_size`. Admin list also accepts `search` for title/address.

| Method and path | Caller | Input | Success |
|---|---|---|---|
| `GET /api/admin/properties` | Admin | Query filters above | Paginated property objects, including buyer/sale data |
| `GET /api/admin/properties/{id}` | Admin | — | One complete property, building details, ordered images, buyer details |
| `POST /api/admin/properties` | Admin | Property object below | `200` property object |
| `PUT /api/admin/properties/{id}` | Admin | Full property object below | Updated property; `updated_at` changes |
| `DELETE /api/admin/properties/{id}` | Admin | — | `204`; image files and building details are removed, queries remain with a null property link |
| `PATCH /api/admin/properties/{id}/status` | Admin | Available or sold object below | Updated property |
| `GET /api/public/properties` | Public | Public filters above | Paginated public property objects |
| `GET /api/public/properties/{id}` | Public | — | One public property; hidden sold listings return 404 |

Property create/update object:

```json
{
  "title": "Garden plot",
  "property_type": "plot",
  "address": "Full address",
  "length": 40,
  "width": 30,
  "description": "Optional details",
  "price": 2500000,
  "latitude": null,
  "longitude": null,
  "maps_url": null,
  "building_details": null
}
```

For `house` and `flat`, `building_details` is required and contains `bedrooms`, `kitchens`, `bathrooms`, `building_area`, and optional `garden_area` / `parking_area` (default 0). Plots must send `building_details: null`. Length/width must be positive; price and areas cannot be negative. `maps_url` may be null or empty; otherwise whitespace is trimmed and it must start with `http://` or `https://` and be no longer than 2000 characters.

Status request for available: `{ "status": "available" }` clears buyer, sold date, and sale price. To mark sold, send `status`, `buyer_name`, `buyer_phone`, `buyer_whatsapp_number`, optional `buyer_email`, optional ISO `sold_at`, and optional non-negative `sale_price`.

### Images (admin only)

| Method and path | Input | Success |
|---|---|---|
| `GET /api/admin/properties/{id}/images` | — | Ordered image objects |
| `POST /api/admin/properties/{id}/images` | Multipart form, repeat field `files` | Uploaded images; JPG/PNG/WebP, 5 MB each, max 10 per property |
| `DELETE /api/admin/properties/{id}/images/{image_id}` | — | `204`, including Cloudinary deletion |

## Public enquiries

| Method and path | Caller | Input | Success |
|---|---|---|---|
| `POST /api/public/queries` | Public | `{ "name":"…", "phone":"…", "whatsapp_number":"…", "property_id":null, "email":null, "message":null }` | `{ "id": 1, "status":"new", "message":"Thank you. Your enquiry has been received." }` |

Name, phone, and WhatsApp are required. Phone numbers are normalized; 10-digit Indian numbers receive the `+91` country prefix. The first customer name is retained; a missing customer email may be filled. At most 5 enquiries per visitor IP per hour are accepted by this single-process limiter. On Render, run Uvicorn with proxy headers enabled as shown in the server README so the limiter sees the visitor IP.

## Queries (admin)

| Method and path | Input | Success |
|---|---|---|
| `GET /api/admin/queries` | `status`, `property_id`, `date_from`, `date_to`, `search` (name/phone), `sort`, `page`, `page_size` | Paginated query objects with customer and property |
| `GET /api/admin/queries/{id}` | — | One query with related customer and property |
| `PATCH /api/admin/queries/{id}/resolve` | — | Sets `resolved` and `resolved_at`; resolving an already resolved query preserves its original time |
| `PATCH /api/admin/queries/{id}/reopen` | — | Sets `new` and clears `resolved_at`; reopening an already new query leaves it unchanged |
| `POST /api/admin/queries/{id}/reply-email` | `{ "subject":"…", "body":"…" }` | Sends email; does not resolve the query |
| `GET /api/admin/queries/{id}/whatsapp-link?message=…` | URL-encoded reply message | `{ "url":"https://wa.me/…" }` |
| `GET /api/admin/queries/stats` | — | Counts, average resolution seconds, and counts by property |

## Customers and dashboard (admin)

|---|---|---|
| `GET /api/admin/customers` | `search`, `page`, `page_size` | Paginated customers and query counts |

## Health

`GET /health` returns `200 {"status":"ok","database":"connected"}` when PostgreSQL answers `SELECT 1`; otherwise it returns a generic 503 response.
